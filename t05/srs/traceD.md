# Разбор работы рекурсивного метода F(n)

Дан метод:
```csharp
static int F(int n) { if (n <= 1) return 1; return n * F(n - 1); }
```

---

### Пункт 1. Терминальное условие и рекурсивный переход
* **Базовый случай (терминальная ветка):** конструкция `if (n <= 1) return 1;`. Здесь погружение в рекурсию останавливается: как только параметр `n` доходит до единицы (или меньше), метод сразу отдаёт `1` без новых самовызовов.
* **Шаг рекурсии:** выражение `return n * F(n - 1);`. Текущий вызов откладывает операцию умножения и обращается сам к себе, но с аргументом, уменьшенным на единицу (`n - 1`).

---

### Пункт 2. Пошаговая трассировка вызова `F(4)`

**Фаза спуска (накопление вызовов в стеке):**
* Уровень 1: вызывается `F(4)` -> для расчёта `4 * F(3)` требуется узнать значение `F(3)`.
* Уровень 2: вызывается `F(3)` -> для расчёта `3 * F(2)` требуется узнать значение `F(2)`.
* Уровень 3: вызывается `F(2)` -> для расчёта `2 * F(1)` требуется узнать значение `F(1)`.
* Уровень 4: вызывается `F(1)` -> срабатывает условие `1 <= 1`, метод сразу возвращает `1`.

**Фаза подъёма (раскрутка стека и подсчёт):**
* Уровень 4 (`F(1)`) отдаёт наверх число `1`.
* Уровень 3 (`F(2)`) перемножает: `2 * 1` и отдаёт `2`.
* Уровень 2 (`F(3)`) перемножает: `3 * 2` и отдаёт `6`.
* Уровень 1 (`F(4)`) перемножает: `4 * 6` и отдаёт итоговый ответ `24`.

#### Сводная таблица выполнения

| Вызов | Глубина | Возвращает |
| :---: | :---: | :---: |
| `F(4)` | 1 | `24` (так как `4 * 6`) |
| `F(3)` | 2 | `6` (так как `3 * 2`) |
| `F(2)` | 3 | `2` (так как `2 * 1`) |
| `F(1)` | 4 | `1` (выход из рекурсии) |

---

### Пункт 3. Поведение `F(-1)` при проверке `n == 1`
Если переписать проверку выхода в виде `if (n == 1) return 1;`, то запуск `F(-1)` приведёт к **бесконечному зацикливанию рекурсии** и аварийной остановке программы с исключением **`StackOverflowException`** (переполнение стека вызовов).

**Причина:**
Переданное число `-1` не равно `1`, поэтому условие остановки пропустит этот вызов. Далее метод начнёт вызывать `F(-2)`, затем `F(-3)`, `F(-4)` и так далее в сторону отрицательной бесконечности. Поскольку на каждом шаге аргумент уменьшается на единицу, он никогда не станет равен `1`. Каждый незаконченный вызов занимает память в стеке, и когда свободное место в стеке закончится, среда выполнения выбросит ошибку переполнения стека.
